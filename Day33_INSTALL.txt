SketchyAR Day 33.2 — Quadrant-based contour alignment (app v0.33.0)

INSTALL
1. Extract this archive.
2. Copy the CONTENTS of ar-drawing/ into the existing Git repository folder (the folder that contains .git).
3. Replace files when prompted. Do not delete .git and do not run git init.
4. From the repository root:
   cd app
   npm ci --include=dev
   npm run typecheck
   npm run build
   node --experimental-strip-types --test tests/*.test.mjs
   cd ..
5. Publish the updated app to GitHub Pages and open it on the iPhone.

HOW THE ALIGNMENT WORKS
1. Open a drawing with its reference image loaded.
2. Put a plain white sheet on a darker, matte surface; keep all four page edges visible.
3. Draw distinctive parts of the reference in at least two neighbouring regions of the imagined 4x4 grid. Corners, turns and intersections help more than a single straight line.
4. Hold the phone still and approximately perpendicular to the flat page.
5. Unlock the overlay if it is locked, then tap the former mirror button (now the contour-alignment button).
6. The app samples five frames, checks paper stability, fuses persistent marks, finds a 4x4 coarse match and checks/refines it with 6x6 local cells.
7. If enough adjacent cells agree, the app places the complete image with one shared scale/rotation/translation and saves the placement.
8. If it refuses a match, add more distinctive marks in neighbouring areas and scan again. The existing overlay position is kept on failure.

RECOMMENDED TESTS
- Light graphite pencil, then dark pen/marker (separately).
- Two adjacent cells, then three or four adjacent cells.
- Camera steady versus deliberate movement (movement should be rejected).
- Different camera distances while keeping the page flat and fully visible.

LIMITS
- Processing is local; no image upload, external service, AI model or extra camera stream.
- The 4x4 and 6x6 cells contribute evidence to one global transform; the image is not split into separately moving tiles.
- The editor currently applies translation, uniform scale and rotation, not perspective homography. Keep the phone approximately perpendicular to the paper.
- The sheet must stand out from its background. White table/background merging with the page, strong glare/shadows, occlusion, repeated shapes and very faint lines can prevent recognition.
- Real iPhone Safari/Home Screen testing remains necessary. The included synthetic regression suite cannot guarantee camera performance on physical paper.
