# Ден 16 — Лицензионен и fixture инвентар (P0 checklist)

## Статус към v0.16.0

- Основният проект е в публично репозитори. Изборът на лиценз за **собствения код** изисква изрично решение на автора; не добавяме произволен MIT/GPL лиценз от името на автора.
- До приемането на лиценз и NOTICE инвентар не бива да се твърди, че проектът е open-source с конкретен лиценз.
- Публичните npm пакети `eruda`, `vite`, `typescript`, Pyodide/NumPy runtime и бинарните ресурси/шрифтове изискват проверка на конкретните им лицензи и включените notice файлове преди публично release. Отделно се проверяват всички AI weights, ако бъдат добавени.
- `Caveat` font file и Day 8 vendor scripts имат самостоятелен лицензен път — не публикуваме шрифтови файлове без лицензна проверка.
- Снимките за бенчмарк и тестове, включително изображения на търговски марки или лични портрети, **не трябва** да се комитват без изрично разрешение; в repo могат да се съхраняват метаданни/хешове и числени резултати.
- `.gitignore` включва целеви правила за лични ZIP backups, диагностични JSON, private fixtures и снимки от потребителя. Това **не защитава вече проследени от Git файлове**; изпълнявай `git ls-files` / `git status` преди commit.

## Преди публична версия

1. Авторът избира и одобрява `LICENSE` (или изрично без отворен лиценз).
2. Подготвя се актуален `NOTICE` с всички действително разпространявани JS/Python/шрифтови/моделни зависимости, техните версии и изискваните attribution.
3. Проверява се Git историята за лични/неразрешени изображения (без публикуване на тези файлове в доклади).
4. Нито един външен AI checkpoint не влиза в бандъла преди самостоятелен license audit.
